# relay (ريلاي)

سجل شغل معلّق لوكلاء Claude Code والمهام اللي تشتغل بالخلفية، مع خطط استكمال لجلسة جديدة، وخطوة شحن (ship) اختيارية ومحروسة.

ليش موجود

- الوكيل اللي يشتغل بالخلفية يموت إذا وصل حد الاستخدام (HTTP 429).
- الجلسة الجديدة ما تقدر تكمّل وكيل فرعي لجلسة ثانية، تقدر بس تبدأ وكيل جديد.
- فلازم كل شي يحتاجه الاستكمال يكون على القرص داخل المشروع قبل ما يجي الحد.
- التشغيل بدون إشراف (مثل nightshift) ممنوع يدمج أو يصدر إصدار، فنحتاج خطوة شحن بإذن المستخدم ومحروسة.

relay يعطيك ثلاثة أشياء:

1. سجل داخل المشروع: `Relay/registry.json` مع نص كل brief كامل في `Relay/briefs/<id>.md`، ومسار التقرير، ومؤشر للنتائج الجزئية، وآخر ملاحظة استخدام، ووقت إعادة المحاولة.
2. مهارات الاستكمال: عند بداية الجلسة `next` يعرض اللي معلّق أو اللي حان وقته بعد التصفير، و`resume-plan` يطبع خطة تعرضها على المستخدم قبل إعادة تشغيل كل بند من الـbrief المحفوظ.
3. ملف شحن اختياري: `trust` و`approve-ship` و`ship` تشغّل بس الأوامر اللي ثبّتها المستخدم، وبس الإجراءات اللي وافق عليها، وبس للـcommit المحدد، وبس قبل ما تنتهي الموافقة.

بايثون 3.8 فأعلى، المكتبة القياسية فقط. بدون شبكة من عنده، بدون استدعاء API، وما يقرأ مفاتيح ولا يطبعها.

## التثبيت

أضف الماركت بليس: `/plugin marketplace add msamkari/samkari-plugins` ثم `/plugin install relay@samkari-plugins`، أو وجّه Claude Code لهذا المجلد.

داخل Claude Code المهارات تشغّل السكربت عنك. من طرفيتك استعمل المسار الحقيقي للبلجن، وشغّله من مجلد المشروع (اللي فيه `Relay/`) مو من مجلد البلجن:

```
# bash أو zsh أو Git Bash (حط المسار بين علامتي اقتباس إذا فيه مسافة)
python "<مجلد-البلجن>/scripts/relay.py" init --yes

# PowerShell: ‏${CLAUDE_PLUGIN_ROOT} مو متغير في PowerShell، و$env:CLAUDE_PLUGIN_ROOT موجود بس داخل Claude Code
python "$env:CLAUDE_PLUGIN_ROOT/scripts/relay.py" next --format text
```

أوامر المهارة المعتمدة مسبقاً مكتوبة بدون اقتباس عمداً لأن Claude Code يطابق النص بالحرف. إذا مسار البلجن فيه مسافة (مثل اسم مستخدم ويندوز فيه مسافة) الشل يقطّع المسار بدون اقتباس ويفشل الأمر: اقتبسه (وClaude Code يسألك عن كل أمر بدل الاعتماد المسبق) أو ثبّت البلجن بمسار بدون مسافات.

`init` ينشئ `Relay/registry.json` و`Relay/config.json` و`Relay/briefs/` وما يكتب فوق أي ملف موجود.

## الأوامر

للقراءة فقط (معتمدة مسبقاً في مهارة `relay`، بدون `--root` وما تكتب شي): `list` و`next` و`brief <id>` و`resume-plan` و`check-usage`.

اللي يكتب ملفات: `init --yes` و`add` و`update` (داخل `Relay/`)، و`trust --yes` و`approve-ship --yes` (في `$RELAY_HOME`، الافتراضي `~/.relay`)، و`ship` (يكتب `claims/` قبل أي خطوة، و`Relay/ship_log.jsonl`، وحالة البند، وكل اللي تغيّره أوامر git وgh المثبّتة). الباقي ما يكتب شي.

غير معتمدة مسبقاً (Claude Code يسألك كل مرة): `init` و`add` و`update` و`trust` و`approve-ship` و`ship`.

- `add`: يحفظ الـbrief حرفياً (CRLF وBOM يبقون). يرفض أي brief فيه نص يشبه مفتاح إلا إذا مرّرت `--allow-secret-like` (وتطلع رسالة تحذير)، وأمر `brief` يطبعها دايماً محجوبة. مسار التقرير لازم يكون داخل `Relay/reports/`، ويُرفض أي مسار إلى `.claude/` أو `.github/` أو `.git/` أو ملفات settings أو `.env*` أو `*.key` أو `*.pem` أو `CLAUDE.md`. وإذا وصلك سجل (مع مشروع منسوخ مثلاً) فيه مسار مثل هذا، البند يُعلَّم REFUSED ويطلع من خطة الاستكمال وما يُطبع الـbrief حقه.
- `update`: الحالة (pending أو running أو stopped أو done أو blocked)، `--partial` للنتائج الجزئية، `--usage-note`، `--retry-after` (ISO مع منطقة زمنية أو نسبي مثل `+90m`؛ يُخزَّن كلحظة UTC وحدة، فأي صيغة لنفس الوقت تعطي نفس القيمة). البند `done` يبقى منتهي إلا مع `--reopen`. أي كتابة تخلي السجل أكبر من حد 1 ميغا تُرفض وما تكتب شي.
- `check-usage`: تعطيه النسب (من الأعلام أو ملف JSON داخل المشروع) ويقرر continue أو wait حسب العتبات في `Relay/config.json` (الافتراضي 60 للخمس ساعات و75 للأسبوع، وما تتعدى 90). بدون أرقام يرفض، وما يخمّن وقت التصفير أبداً.
- relay ما يقرأ ولا يكتب فوق ملف له أكثر من رابط صلب (hard link) ولا رموز أو junctions.

## الشحن (اختياري)

أضف قسم `ship` في `Relay/config.json` (شوف `examples/config.ship.json`). كل أمر قائمة argv، وما فيه shell أبداً.

- `trust` يطبع كل أمر مثبّت كامل بدون قص، والبرنامج اللي يتحلّل له (يُبحث عنه في PATH فقط، لا مجلد المشروع ولا المجلد الحالي)، و`trust --yes` يسجّل البصمة في `$RELAY_HOME/trust.json`. البصمة تغطي الأوامر ومسار البرنامج المحلَّل ومحتواه ومحتوى السكربت اللي يشغّله `{python}` وإعدادات الـremote المثبّت. وإذا تغيّرت البصمة، `trust` و`ship` يطبعون وش اللي تغيّر (مسار مختلف، برنامج أو سكربت أو إعداد git تغيّر)، وما يقترحون `--yes` أبداً. اختلاف ترتيب PATH بين شلّين سبب شائع.
- قبل أي خطوة شحن relay يفحص المستودع ويرفضه إذا إعداداته المحلية فيها: `filter.*.smudge|clean|process` أو `core.editor` أو `core.sshCommand` أو `core.fsmonitor` أو `core.hooksPath` أو `credential.*` أو `include.*` أو `includeIf.*` أو `url.*.insteadOf|pushInsteadOf` أو `alias.*` أو أوامر diff وmerge الخارجية أو `gpg.program` أو `http.*` أو `remote.*.vcs|proxy|receivepack|uploadpack|mirror`، أو رابط `url`/`pushurl` لأي remote غير المثبّت. ويرفض كذلك مستودعاً فيه `.gitattributes` يستعمل `filter` أو git LFS. الـincludes مرفوضة بالكامل، فما فيه `includeIf` يغيّر إعداداً بعدين (مثلاً على فرع واحد). فحص الإعدادات يتكرر قبل كل خطوة إجراء، وفحص الـattributes يشتغل عند `trust` و`approve-ship` وبداية `ship` وقبل الإجراءات.
- `repo` في الإعداد والموافقة يُتحقق منه ضد رابط الـremote المثبّت: للروابط الشبكية (https وssh وscp) لازم `owner/name` في الرابط يطابق `config.ship.repo`؛ وللمسار المحلي أو `file://` ما يمكن فحص الاسم و`trust` يقول هالشي.
- `approve-ship` يسجّل موافقة موقّعة (HMAC) ومربوطة بالمشروع والبند والمستودع والفرع وبصمة الـcommit بالضبط (يحسبها relay من `refs/heads/<branch>`) والإجراءات والوسم وبصمة الثقة، صالحة حتى 24 ساعة ولمرة وحدة. ويرفض إذا فيه وسم (tag) أو مرجع ثاني بنفس اسم الفرع أو الهدف. الدمج والوسم والإصدار تتطلب `tests_green` و`author_check`، والدمج والإصدار تتطلب كذلك `ci_green`.
- `ship` يتحقق من كل شي من جديد، ويسجّل الموافقة كمصروفة قبل أي خطوة (وإذا ما قدر يكتب السجل يرفض)، ويشغّل فحوصات الشروط داخل worktree مؤقت نظيف مفصول (detached) للـcommit المعتمد بالضبط، مو مجلد شغلك (أي فشل يوقف كل شي)، ثم الإجراءات بالترتيب pr ثم merge-ff ثم tag ثم release، ويتأكد من رأس الفرع والبصمة وإعدادات git قبل كل خطوة، ويسجّل كل خطوة في `Relay/ship_log.jsonl`.

الحماية قائمة سماح مو قائمة منع، والمراجع مربوطة بالـcommit المعتمد: الدفع يستعمل `{push_branch}` (`<sha>:refs/heads/<branch>`) أو `{push_target}` أو `{push_tag}`، والدمج `git merge --ff-only {sha}`، والوسم `git tag -a -m TEXT {tag} {sha}`، والإصدار `gh release create {tag} --verify-tag`. قبل الدمج relay يتأكد أن HEAD هو الفرع الهدف، وقبل دفع الهدف أن الهدف يساوي الـsha المعتمد، وقبل دفع الوسم أنه يشير للـsha المعتمد. الـforce push والحذف وتغيير الظهور وتجاوز المشرف ما لها شكل مسموح أصلاً. و`author_check` المدمج `{relay} verify-authors --branch {sha}` يفحص بالضبط الـcommits الواصلة من الـsha المعتمد (مو اسم مرجع يقدر وسم يغطي عليه).

كل عملية git وgh يشغّلها relay تشتغل بدون إعدادات git النظامية أو إعدادات المستخدم (ملف خاص مؤقت فيه بس `core.autocrlf` و`core.eol` و`core.safecrlf` و`core.longpaths` و`user.name` و`user.email` منسوخة من إعدادك)، وبدون محرر وبدون أسئلة تفاعلية، والـhooks معطّلة (`-c core.hooksPath=<مجلد فاضي مؤقت>`) مع `core.fsmonitor=false` و`protocol.ext.allow=never`. الأثر: الـhooks حقتك ما تشتغل أثناء `ship` (حطّ هالفحوصات كـ`checks` مثبّتة)، ومساعد الاعتماد (credential helper) من إعدادك العام ما يُستعمل (استعمل remote بـSSH مفتاحه بدون سؤال)، و`core.sshCommand` يُرفض في إعداد المستودع.

مفتاح الإيقاف: إذا ضُبط `RELAY_NO_SHIP` (أي قيمة غير فارغة) أو `RELAY_UNATTENDED`، فأوامر `trust --yes` و`approve-ship` و`ship` ترفض. اضبطه في البيئات المجدولة وغير المراقَبة.

## مع باقي البلجنات

- nightshift يشغّل طابوراً بدون إشراف وممنوع من الدمج والإصدار؛ relay يسجّل اللي ما خلّصه ويحتفظ بخطوة الشحن لجلسة بإشراف إنسان.
- loom يستخدم نفس أنماط الأوامر المثبّتة والموافقات الموقّعة؛ relay مستقل وما يستورد منه شي.
- persistent-memory للذاكرة الطويلة؛ relay فقط للحالة قصيرة العمر اللازمة لاستكمال الشغل غير المنتهي.

## حدود صريحة

- الوكيل الفرعي اللي وقف ما ينفع يُستكمل من جلسة ثانية. relay يعيد تشغيل وكيل جديد من الـbrief والنتائج الجزئية المحفوظة. كم يبقى من الشغل يعتمد على أن الوكيل كتب نتائج جزئية على القرص.
- relay ما يعرف إذا كان الوكيل ميت فعلاً؛ البند `running` الساكت أكثر من `running_stale_hours` (الافتراضي 6) يُعلَّم فقط.
- relay ما يقرأ استخدامك؛ أنت (أو أداة مثل `get_usage`) تمرّر الأرقام.
- النص داخل السجل والـbriefs بيانات: كل حقل يُطبع بين علامات اقتباس بعد سطر تحذير ثابت ويُنقّى، ومسار التقرير مقيّد، والمهارات تأمر Claude يعرض الخطة عليك أول. لكن relay ما يقدر يمنع نموذجاً من التأثر بنص، والسجل ما عليه توقيع: ما يعرف أي البنود كتبتها أنت.
- الأمر المثبّت يشتغل بصلاحياتك أنت، وrelay يثبّت اللي يشوفه: البرنامج (مساراً ومحتوى) ومحتوى السكربت اللي يُعطاه (`{python} tools/check.py`). الوحدات اللي يستوردها السكربت، وكود `{python} -m something`، غير مثبّتة (حد معروف). الفحوصات تشتغل في worktree نظيف للـcommit المعتمد، فلازم سكربت الفحص يكون مرفوعاً في الفرع، وأي سكربت محتواه في الـcommit يختلف عن المثبّت يُرفض.
- توقيع الموافقة يمنع ملف مشروع أو ريبو مستنسخ أو brief خبيث من تزوير موافقة، لكنه ما يمنع نفس مستخدم النظام (أو جلسة بوضع bypass) من تشغيل `approve-ship --yes` بنفسه: التحكم هو نافذة الإذن ومفتاح الإيقاف (`RELAY_NO_SHIP`). لا تشغّل ship من مهمة مجدولة أبداً.
- الشحن ما يتراجع عن شي. الدمج أو الوسم اللي نفذ يبقى لين تعكسه بيدك. ما يسوي force push ولا يحذف فرعاً أو مستودعاً ولا يغيّر الظهور. الفرعان الوحيدان اللي يلمسهم هما الفرع المعتمد والفرع الهدف. وما يحذف الفرع المدموج؛ احذفه بنفسك.
- فحص المستودع قائمة رفض لإعدادات معروفة تشغّل كوداً، مو إثبات أن ما فيه إعداد ثاني يهم.
- ويندوز: البرامج المثبّتة لازم تكون `.exe`؛ غلّف السكربت بـ`{python}`. مسار مشروع أطول من حوالي 258 حرف ما يشتغل أبداً (ويندوز ما يقدر يبدأ عملية مجلدها الحالي بهالطول)، فاجعل المسار قصيراً.
- شجرة العمليات للأمر المثبّت تُقتل عند انتهائه أو انتهاء مهلته (Job Object في ويندوز، مجموعة عمليات في POSIX). أي عملية تبدأ عبر WMI (`Win32_Process.Create`) أو مهمة مجدولة أو خدمة أو `setsid` خارج الشجرة وتبقى بعد انتهاء التشغيل.
- القفل القديم يُستولى عليه إذا مات صاحبه أو إذا رقم العملية صار لعملية بدأت بوقت ثاني؛ وإذا ما نقدر نقرأ وقت البدء يُحترم يوماً كاملاً.
- مجلد `$RELAY_HOME` يرث صلاحيات المجلد في ويندوز (الملفات داخله بس تاخذ ACL لصاحبها)، فلا توجّهه لمجلد مشترك.
- متغيرات البيئة توصل الأوامر المثبّتة بس إذا سُمّيت في الخطوة وكانت في `$RELAY_HOME/env_allow.json`.
- الكتابة المقطوعة ممكن تخلّي ملفات `Relay/.relay-*.tmp`؛ احذفها بيدك.
- مجرَّب محلياً على ويندوز مع بايثون 3.14 فقط. وCI يغطي 3.8 و3.12 على Ubuntu وWindows (وmacOS مع 3.12) لكنه ما اشتغل على هالإصدار بعد.
