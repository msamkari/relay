# relay (ريلاي)

سجل شغل معلّق لوكلاء Claude Code والمهام اللي تشتغل بالخلفية، مع خطط استكمال لجلسة جديدة، وخطوة شحن (ship) اختيارية ومحروسة.

ليش موجود

- الوكيل اللي يشتغل بالخلفية يموت إذا وصل حد الاستخدام (HTTP 429).
- الجلسة الجديدة ما تقدر تكمّل وكيل فرعي لجلسة ثانية، تقدر بس تبدأ وكيل جديد.
- فلازم كل شي يحتاجه الاستكمال يكون على القرص داخل المشروع قبل ما يجي الحد.
- التشغيل بدون إشراف (مثل nightshift) ممنوع يدمج أو يصدر إصدار، فنحتاج خطوة شحن بإذن المستخدم ومحروسة.

relay يعطيك ثلاثة أشياء:

1. سجل داخل المشروع: `Relay/registry.json` مع نص كل brief كامل في `Relay/briefs/<id>.md`، ومسار التقرير، ومؤشر للنتائج الجزئية، وآخر ملاحظة استخدام، ووقت إعادة المحاولة.
2. مهارات الاستكمال: عند بداية الجلسة `next` يعرض اللي معلّق أو اللي حان وقته بعد التصفير، و`resume-plan` يطبع الخطوات بالضبط لاستكمال كل بند بإعادة التشغيل من الـbrief المحفوظ.
3. ملف شحن اختياري: `trust` و`approve-ship` و`ship` تشغّل بس الأوامر اللي ثبّتها المستخدم، وبس الإجراءات اللي وافق عليها، وبس للـcommit المحدد، وبس قبل ما تنتهي الموافقة.

بايثون 3.8 فأعلى، المكتبة القياسية فقط. بدون شبكة، بدون استدعاء API، وما يقرأ مفاتيح ولا يطبعها.

## التثبيت

أضف الماركت بليس اللي يحتويه ونفّذ `/plugin install relay`، أو وجّه Claude Code لهذا المجلد. بعدها داخل مجلد المشروع:

```
python scripts/relay.py init --yes
```

`init` ينشئ `Relay/registry.json` و`Relay/config.json` و`Relay/briefs/` وما يكتب فوق أي ملف موجود.

## الأوامر

للقراءة فقط (معتمدة مسبقاً في مهارة `relay`، بدون `--root` وما تكتب شي): `list` و`next` و`brief <id>` و`resume-plan` و`check-usage`.

غير معتمدة مسبقاً (Claude Code يسألك كل مرة): `init` و`add` و`update` و`trust` و`approve-ship` و`ship`.

- `add`: يحفظ الـbrief حرفياً (CRLF وBOM يبقون). يرفض أي brief فيه نص يشبه مفتاح (`sk_` و`ghp_` و`github_pat_` و`AKIA` و`xox` وترويسة مفتاح خاص وتوكنات hex أو base64 طويلة) إلا إذا مرّرت `--allow-secret-like`. وأمر `brief` يطبعها دايماً محجوبة.
- `update`: الحالة (pending أو running أو stopped أو done أو blocked)، `--partial` للنتائج الجزئية، `--usage-note`، `--retry-after` (ISO مع منطقة زمنية أو نسبي مثل `+90m`). البند `done` يبقى منتهي إلا مع `--reopen`.
- `check-usage`: تعطيه النسب (من الأعلام أو ملف JSON داخل المشروع) ويقرر continue أو wait حسب العتبات في `Relay/config.json` (الافتراضي 60 للخمس ساعات و75 للأسبوع، وما تتعدى 90). بدون أرقام يرفض، وما يخمّن وقت التصفير أبداً.

## الشحن (اختياري)

أضف قسم `ship` في `Relay/config.json` (شوف `examples/config.ship.json`). كل أمر قائمة argv، وما فيه shell أبداً.

- `trust` يطبع كل أمر مثبّت كامل (بعد التنقية) والبرنامج اللي يتحلّل له (يُبحث عنه في PATH فقط، لا مجلد المشروع ولا المجلد الحالي)، و`trust --yes` يسجّل البصمة في `$RELAY_HOME/trust.json`. البصمة تغطي الأوامر والبرامج ومحتوى أي سكربت يشغّله `{python}`.
- `approve-ship` يسجّل موافقة موقّعة (HMAC) ومربوطة بالمشروع والبند والمستودع والفرع وبصمة الـcommit بالضبط والإجراءات والوسم وبصمة الثقة، صالحة حتى 24 ساعة ولمرة وحدة. الدمج والوسم والإصدار تتطلب `tests_green` و`author_check`، والدمج والإصدار تتطلب كذلك `ci_green`.
- `ship` يتحقق من كل شي من جديد، يطالب الموافقة بشكل ذري، يشغّل فحوصات الشروط أولاً (أي فشل يوقف كل شي)، ثم الإجراءات بالترتيب pr ثم merge-ff ثم tag ثم release، ويتأكد من رأس الفرع قبل كل خطوة، ويسجّل كل خطوة في `Relay/ship_log.jsonl`.

الحماية قائمة سماح مو قائمة منع: كل إجراء يقبل بس أشكال أوامر محددة بالضبط. الـforce push والحذف وتغيير الظهور وتجاوز المشرف ما لها شكل مسموح أصلاً.

مفتاح الإيقاف: إذا ضُبط `RELAY_NO_SHIP` (أي قيمة غير فارغة) أو `RELAY_UNATTENDED`، فأوامر `trust --yes` و`approve-ship` و`ship` ترفض. اضبطه في البيئات المجدولة وغير المراقَبة.

## مع باقي البلجنات

- nightshift يشغّل طابوراً بدون إشراف وممنوع من الدمج والإصدار؛ relay يسجّل اللي ما خلّصه ويحتفظ بخطوة الشحن لجلسة بإشراف إنسان.
- loom يستخدم نفس أنماط الأوامر المثبّتة والموافقات الموقّعة؛ relay مستقل وما يستورد منه شي.
- persistent-memory للذاكرة الطويلة؛ relay فقط للحالة قصيرة العمر اللازمة لاستكمال الشغل غير المنتهي.

## حدود صريحة

- الوكيل الفرعي اللي وقف ما ينفع يُستكمل من جلسة ثانية. relay يعيد تشغيل وكيل جديد من الـbrief والنتائج الجزئية المحفوظة. كم يبقى من الشغل يعتمد على أن الوكيل كتب نتائج جزئية على القرص.
- relay ما يعرف إذا كان الوكيل ميت فعلاً؛ البند `running` الساكت أكثر من `running_stale_hours` (الافتراضي 6) يُعلَّم فقط.
- relay ما يقرأ استخدامك؛ أنت (أو أداة مثل `get_usage`) تمرّر الأرقام.
- النص داخل السجل والـbriefs بيانات وتُنقّى عند الطباعة، لكن relay ما يقدر يمنع نموذجاً من التأثر بها؛ المهارات تأمر Claude بتجاهل أي تعليمات فيها.
- توقيع الموافقة يمنع ملف مشروع أو ريبو مستنسخ أو brief خبيث من تزوير موافقة، لكنه ما يمنع نفس مستخدم النظام (أو جلسة بوضع bypass) من تشغيل `approve-ship --yes` بنفسه: التحكم هو نافذة الإذن ومفتاح الإيقاف. لا تشغّل ship من مهمة مجدولة أبداً.
- الشحن ما يتراجع عن شي. الدمج أو الوسم اللي نفذ يبقى لين تعكسه بيدك. ما يحذف الفرع المدموج أيضاً؛ احذفه بنفسك.
- الفحوصات والأوامر تشتغل بصلاحياتك أنت. متغيرات البيئة توصلها بس إذا سُمّيت في الخطوة وكانت في `$RELAY_HOME/env_allow.json`.
- على ويندوز البرامج المثبّتة لازم تكون `.exe` (لا `.bat` ولا `.cmd` ولا `.ps1`)؛ غلّف السكربت بـ`{python}`.
